SAP is a global leader in enterprise software. Its product teams were working from several overlapping component libraries, and developers on the project often couldn’t tell which version of a component they were supposed to implement.

Our audit found 5 different input components across 3 libraries.

Design System Consultant, brought in through Valor Software for a short, focused engagement of about two months. I worked with the SAP designers, engineers and product managers who maintained the existing libraries.

Instead of trying to fix everything at once, we picked one high-traffic component, the Input field, and used it as the reference for how every component should be built, documented, versioned and shipped.

  1. AuditAudited 3 libraries and mapped 5 duplicated input components, their variants and owners.
  2. One source of truthRebuilt the Input with 64 variants: 5 interaction states, 5 value states and 2 densities (Compact and Cozy), in light and dark themes.
  3. DocumentationAnatomy, behaviour and structure, plus usage guidelines and accessibility notes.
  4. VersioningVersions and release notes, so teams always know which version is current.
  5. StorybookConnected the design component to the developers’ library, using the workflow already proven on Studytube.
  6. HandoverPresented the approach to the teams and handed the process over to the internal design-system owners.

  • 5 input versions became 1.
  • The Input became the template for the rest of the library.
  • Several teams moved to the new versioning and documentation process.
  • Developers had one Input to build from.
